# ADR 0028 — Layered image evaluation corpus

- Status: Accepted
- Date: 2026-09-05

## Context

SightLint can accumulate technically correct parser stages while still failing to become the intended product: a reliable detector of visual and interaction-quality problems. Unit tests and isolated malformed-image cases prove implementation properties, but they do not preserve a growing, reviewable statement of what representative artifacts contain and what SightLint should eventually detect.

The project needs an evaluation corpus early, before screenshot structure inference or recommended design policies are introduced. The corpus must distinguish facts that the current engine can assert from future ground truth that remains intentionally unsupported.

## Decision

Add a committed, deterministically generated image evaluation corpus with three layers:

1. **Artifact bytes** — valid and intentionally malformed PNG files generated without external image libraries or platform fonts.
2. **Current executable assertions** — JSON-pointer expectations and error contracts that the public `sightlint` binary must satisfy now.
3. **Product ground truth** — medium-neutral regions, peer groups, mutations, and expected future defects that are reviewable even when no current rule consumes them.

The manifest must never convert unsupported ground truth into a passing result. A capability is either covered by executable assertions, explicitly listed as a future target, or absent. The corpus does not calculate a universal quality score.

## Deterministic generation

Use a standard-library Python generator that emits PNG signature/chunks, CRC-32, Adler-32, and stored DEFLATE blocks directly. Do not depend on Pillow, browser rendering, operating-system fonts, zlib compression heuristics, wall-clock time, randomness, or network access.

Generated PNGs and the canonical manifest are committed. `--check` regenerates all expected bytes in memory and fails on a missing, changed, or unexpected generated file. CI runs this check before Rust formatting and tests.

The initial corpus includes:

- transparent padding around visible and fully opaque content;
- an entirely transparent artifact;
- an opaque dashboard-like clean layout;
- a paired dashboard spacing mutation with explicit peer-gap ground truth;
- an opaque multi-color border tie case;
- a translucent-overlay case where opaque-background candidates are inapplicable;
- malformed CRC and invalid-filter mutation cases.

Synthetic regions use rectangles and simple filled bars instead of text rendered through a font stack. This makes geometry deterministic while leaving OCR and typography evaluation for dedicated corpora.

## Pairing and mutation semantics

A mutation case references its clean baseline and records the minimal changed property. The initial spacing pair preserves canvas, palette, surrounding content, and background while changing one peer gap. Later detectors can therefore be evaluated through a targeted mutation-kill obligation rather than broad screenshot similarity.

Ground-truth defects include the intended rule family, target relation, expected measurements, and rationale. They remain non-executable until the corresponding acquisition evidence and rule are implemented.

## Public-binary evaluation

A Rust integration test reads the committed manifest and executes the built `sightlint` binary against every file. It validates:

- manifest schema, unique IDs, file references, baseline references, and region bounds;
- expected exit code and stable error excerpt for malformed cases;
- every current JSON-pointer assertion for valid cases;
- byte-identical repeated `adapt-image` output;
- byte-identical repeated `check-image --format json` output;
- that ground-truth target capabilities are declared separately from current assertions.

The E2E harness does not call adapter internals.

## Growth and governance

New visual heuristics or rules must add or strengthen corpus cases before being considered complete. Regressions are fixed by correcting implementation or explicitly revising reviewed ground truth; tests must not silently weaken expectations.

Future additions should include curated real-world artifacts only when licensing, privacy, provenance, and annotation quality are documented. Synthetic cases remain important for exact boundaries and mutations but are not a substitute for a human-consensus benchmark.

## Verification

The change is complete when:

- generated bytes and manifest are reproducible with `--check`;
- all initial cases execute through the public binary;
- clean/mutation pairing and future target annotations are validated;
- existing parser, rule, report, and exit-code tests remain green;
- Linux, macOS, Windows, and the repository MSRV pass.
