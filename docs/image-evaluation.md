# Image evaluation corpus

SightLint keeps product-evaluation data alongside implementation tests so that technically
correct parser work remains connected to the intended visual-linting outcome.

The corpus lives in `fixtures/evaluation/image/` and is generated by:

```bash
python3 tools/generate_image_evaluation_corpus.py
```

Generated PNG files and `manifest.json` are committed. Verify them without rewriting anything:

```bash
python3 tools/generate_image_evaluation_corpus.py --check
```

## Three distinct layers

Each manifest case contains three deliberately separate kinds of information.

### Artifact bytes

The generator writes PNG chunks, stored DEFLATE blocks, CRC-32, and Adler-32 itself. It uses no
image library, platform font, browser, randomness, network call, or clock. This keeps the initial
corpus byte-identical across development environments.

### Current assertions

`currentAssertions` are obligations the current public `sightlint` binary must satisfy. They use
JSON pointers and one of:

- `equals` for a value comparison
- `exists` for presence or absence
- `length` for a JSON array or object size

The Rust E2E test invokes `adapt-image` and `check-image`; it does not call parser internals.
Malformed cases instead declare an exit code and stable stderr excerpt.

### Product ground truth

`groundTruth` records regions, peer groups, target capabilities, and expected defects. Some of
these annotations intentionally describe capabilities SightLint has not implemented yet. Their
presence does **not** count as a pass and is not included in an aggregate quality score.

A future detector becomes complete only when the relevant ground truth is promoted to executable
assertions or a dedicated evaluation metric with documented precision, recall, and abstention
semantics.

## Clean and mutation pairs

Mutation cases reference a baseline and identify the one property that changed. The first UI pair
keeps the same dashboard canvas and drawing primitives while changing one horizontal card gap.
This gives future repeated-region and spacing detectors a targeted mutation-kill obligation.

When adding a mutation:

1. preserve unrelated artifact properties;
2. identify the baseline case;
3. record the changed measurement and unit;
4. attach a specific expected defect and rationale;
5. avoid weakening current assertions merely to make the new case pass.

## Adding real artifacts later

Synthetic images provide exact boundaries but cannot represent the full diversity of rendered
interfaces. A real-world corpus should be added separately with documented:

- license and redistribution permission
- source provenance and capture environment
- privacy review
- viewport and device scale
- annotation process and reviewer agreement
- expected ambiguity and abstention

Human-consensus data must complement, not replace, deterministic synthetic mutations.
